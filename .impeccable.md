# Impeccable Design Configuration

## Design Context

### Users
Governance board members, funders/program officers, jsPsych core and community developers, and the interested public. They arrive periodically (six-month evaluation cycles, governance meetings, or curiosity after a community announcement) to answer one question: *are the sustainability goals improving?* They are data-literate, time-constrained, and reading — not interacting heavily. The dashboard is also a public accountability artifact linked from a GitHub project board.

### Brand Personality
Utilitarian, trustworthy, unadorned. This is a working instrument, not a marketing page — function over form. Loosely inspired by jsPsych's identity (it should feel like a member of the ecosystem and never clash with jspsych.org), but with no obligation to mirror it. The numbers and their honest presentation ARE the product; decoration that doesn't aid reading is noise.

### Aesthetic Direction
- Light theme only (public/academic reporting context).
- Quarto dashboard on Bootstrap "cosmo"; keep customization lean — this project favors maintainability over visual ambition.
- Charts are the centerpiece: clear axes, direct labeling where possible, restrained styling (current stack: matplotlib/seaborn).
- Anti-references: startup analytics dashboards with hero gradients, glassmorphism, dark-mode-with-neon; anything that would look out of place in a grant report.

### Design Principles
1. **Legibility before beauty** — if a styling choice costs any reading speed or precision, drop it.
2. **Honest data presentation** — no truncated axes for drama, gaps shown as gaps (NaN windows stay visible), definitions stated next to numbers ("How this is measured").
3. **WCAG AA + colorblind-safe** — chart meaning must survive color blindness; never encode meaning in hue alone (use line style/markers/direct labels as backup). Text contrast meets AA.
4. **Consistent idiom across pages** — every page uses the same valuebox/chart/footer grammar so returning readers navigate on habit.
5. **Utilitarian restraint** — prefer removing an element over styling it; whitespace and typographic hierarchy do the layout work.
